# Идея

```plaintext
┌─────────────────────────────────────────────────────────────────┐
│                   ИЗВЕСТНЫЕ АЛГОРИТМЫ И РЕШЕНИЯ                   │
└─────────────────────────────────────────────────────────────────┘

1. КЛАССИЧЕСКОЕ РЕШЕНИЕ (3 прохода, O(1) доп. памяти):
   - Найти середину списка (медленный и быстрый указатели)
   - Развернуть вторую половину списка
   - Слить две половины в требуемом порядке

2. ВРЕМЕННАЯ СЛОЖНОСТЬ: O(n) — необходимо пройти по списку несколько раз
   ДОПОЛНИТЕЛЬНАЯ ПАМЯТЬ: O(1) — только указатели, без хранения в массиве

3. НАЗВАННЫЙ ПАТТЕРН: 
   - "Slow-Fast Pointer" для нахождения середины (алгоритм Флойда для середины)
   - "In-place linked list reversal" (разворот связанного списка)
   - "List merging" (слияние двух списков с чередованием)

4. ПОЧЕМУ НЕЛЬЗЯ ЗА O(1) ВРЕМЕНИ?
   ⚠️ Задача требует прохода по всему списку как минимум один раз,
   так как нужно добраться до конца списка (Ln). 
   Теоретическая нижняя граница: Ω(n), так как нужно посетить все узлы.

5. АЛЬТЕРНАТИВНЫЙ ПОДХОД ЗА O(n) ВРЕМЕНИ И O(n) ПАМЯТИ:
   - Скопировать узлы в список/дек
   - Перестроить связи за один проход
   - Проще для понимания, но использует доп. память
```
